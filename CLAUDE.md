# Quillbound Sheets (the MPMB sheet app): project notes for Claude Code

> **How changes ship: `git push` to `master`.** Cloudflare Pages rebuilds the site on every push; that is where the owner tests. Work on a branch first: every branch gets a preview build at `<branch>.quillbound-sheets.pages.dev` (lowercased, hyphenated). Don't publish the app as a Claude artifact. At the end of a change: run the tests, commit, push (ask the owner before pushing to `master` unless they said to), and say the site redeploys from the push. The owner's accounts, addresses, devices and rules are in `CLAUDE.local.md` (gitignored, never commit them here). How things came to be, with dates: `docs/history.md` (not loaded automatically; read it when you need the why).

A phone-first web app that opens an **MPMB 2024 (5.5e) character sheet PDF** and runs MPMB's own scripts in a stand-in for Adobe Acrobat. Users play and build characters on a phone or tablet; all D&D logic comes from MPMB's code inside their PDF.

- Design doc (decisions, risks, "Still to do", the list of what the sheet has and the app doesn't): link in `CLAUDE.local.md`. Update its "Still to do" when items are done.
- Hosting: Cloudflare Pages from `master` (build `node tools/build-single.js 0.2`; the 0.2 is ignored, the version comes from package.json; output `dist-site`: the full page and `_headers` with COOP/COEP, so the page is cross-origin isolated and MPMB waits for dialogs). **Private behind Cloudflare Access until Joost (MPMB) has looked at it.** Access must list both `quillbound-sheets.pages.dev` and `*.quillbound-sheets.pages.dev` (the wildcard doesn't cover the main address; without it previews are open).
- Test devices: a 6.3" phone (about 393×852 CSS px at 3.1×) and a 10.9" tablet (about 800×1280 at 1.8×), Chrome on Android. The owner also uses Brave.

## Decisions (settled with the owner)

| Topic | Decision |
| --- | --- |
| Look | The app's own layout, phone first (PDF pages are unreadable on phones); no PDF page view |
| Navigation | One scrolling page per screen size + bottom tab bar that jumps to sections and follows the scroll |
| Layout | 1 column phone portrait, 2 columns phone landscape / tablet portrait, 3 columns tablet landscape |
| Save file | The MPMB PDF itself (+ autosave inside the app). A PDF saved by the app works completely in real Acrobat |
| Platform | Web app installed from Chrome; app stores later, if ever |
| Scope | Play **and** build characters |
| Rules | 2024 sheets first; the 2014 (v14) sheets work too; later MPMB versions must keep working |
| Looks | Five themes after MPMB's Colorful and Printer Friendly sheets + "Match my sheet"; no handwriting font; sheet art recreated in CSS, never shipped |

Not yet tried on the phone: the installable app, 2014 sheets, Import from another sheet.

## Files

### Engine side (runs in a Web Worker)
- `src/loader.js`: reads the PDF with pdf-lib into a plain "sheet model": document scripts (name-tree order), fields, widgets, field scripts (K/F/V/C), widget scripts (A/D/U/E/X/Fo/Bl), calculation order, templates, info dictionary, bookmarks.
- `src/engine.js`: the Acrobat stand-in. Field objects, events, `app`/`util`/doc APIs, AForm helpers, `toSource()`, templates/pages, logs (`engine.logSince(seq)`: alerts as `{ title, msg }`, errors as `where: msg`, dialog entries, since `engine.logSeq` was n).
- `src/worker.js`: one sheet per worker. Its own code sits in an IIFE because the global scope belongs to MPMB. `USER_OPS` lists the requests a person starts (sent to the page with the `ready` message as `userOps`); `READS` the requests that change nothing; `ROWS`/`rowCounts` count each kind of line per sheet.
- `src/replay.js`: restart and replay (see Dialogs).
- `src/content.js`: add-on content (MPMB's "Add Extra Materials" and "Source Material"). Runs MPMB's own dialogs with the buttons pressed for the user (`engine.queueDialog`), the picked file queued for `util.readFileIntoStream()` (`engine.queueFile`). The app keeps the three fields that hold the content (`User_Imported_Files.Stringified`, `User Script`, `CurrentSources.Stringified`) in IndexedDB per sheet (file name + size), presets them before `start()`, then runs `restore()` (Source Selection → Apply) to rebuild the dropdowns. Single items: `excludeItems` (see Known gaps).
- `src/spells.js`: `options()` runs MPMB's `AskUserSpellSheet` once with the dialogs' data captured (lists, counts, picks) and cancels at the last dialog; `choose()` writes the picks where those dialogs keep them (`CurrentSpells[caster].selectCa/selectSp/selectPrep/typeList`) and runs `GenerateSpellSheet`; `sheet()` reads the spawned SSfront/SSmore pages back as rows; `tapRow()` presses a row's first-column button; `key()` is a short hash of what the options depend on (`CurrentSpells` as `probe()` leaves it, ability modifiers, level, proficiency bonus, `CurrentSources`, add-on content), also returned by `options()`. The app (`refreshSpells` in ui-spells.js) asks the worker's read-only `spellKey` after each change and runs `spellOptions` only when it differs; opening, making/removing the list, content and page changes force a full refresh (`spellsSoon(true)`).
- `src/classes.js`: MPMB's Class Selection dialog (`SelectClass`): `options()` reads its lists and rows (captured, then cancelled); `apply()` clears every row, picks class, subclass and level per row (pressing their handlers) and presses Apply.
- `src/abilities.js`: MPMB's Ability Scores dialog: `options()` reads `CurrentStats.cols` and the explanation (the ability tooltip), `preview()` uses `getAbilityScoreTotals(i, dialogStore)` and `ASCalcPointBuy`, `apply()` types each changed box and presses Apply.
- `src/writer.js`: writes `engine.exportState()` into the sheet's own PDF with pdf-lib: replays page changes (a spawned template page is a copy of the template page, `/Type /Page`, fields renamed `P<page>.<template>.<name>` under new parent nodes), then values, field/widget changes (flags, TU/TM, Opt, DA, MK colours/caption/icon, BS, Rect, scripts as JavaScript actions), /CO, info, added doc scripts. Draws appearances with `src/appearance.js`; sets NeedAppearances only when it has no appearance data.
- `src/appearance.js`: how text fields, combo boxes and changed button captions look in the saved PDF (see Acrobat fidelity).
- `src/selftest.js`: builds an Elf Wizard 3 and checks 19 results (Node tests only).

### Page side
- Scripts load in `src/index.html`'s order (the single-file build joins them in that order): `features.js`, `ui-core.js` (helpers `$`, `$$`, `el`, the app's lists and `state`, in `window.MPMBUI`), then one IIFE per area that takes what it needs from `MPMBUI` and adds its own functions (calls into other files go through small `U.name(...)` forwarders, so load order doesn't matter), then `app.js` last, which starts the app. A new page script needs a `<script src>` line in index.html and a `cp` in `tools/build.sh`.
  - `ui-dialog.js`: `mpmbDialog`, the renderer for MPMB's dialogs.
  - `ui-pages.js`: companion, Wild Shape, notes and logsheet pages (`rebuildPages` shared by `syncCompanions`/`syncWildShapes`/`syncNotes`/`syncLogs`; `build*`/`refresh*` per kind).
  - `ui-classes.js` (class and ability score screens), `ui-pictures.js`, `ui-spells.js`, `ui-content.js` (add-on content and sources), `ui-import.js` (Import from another sheet), `ui-backup.js` (Settings → Backups).
  - `ui-dice.js`: dice (see Features).
  - `ui-suggest.js`: the app's own suggestion list under a text box with MPMB's names (magic items, feats, weapons, damage types, ammunition, creatures), in place of the browser's `<datalist>` popup, which Brave on Android drew over the page without a background. The `<datalist>` stays (filled by `data-items`); on focus a box's `list` moves to `data-list`. Names starting with the typed text first, then a word starting with it, then any containing it. A tap picks (`click`); a swipe scrolls the list (`touch-action: pan-y`, `overscroll-behavior: contain`) and picks nothing; the list's `mousedown` is cancelled so the box keeps focus (picking on `pointerdown` picked the item under the finger at the start of every swipe). A pick sends one change (the browser's on blur, or its own when the browser sends none).
  - `app.js`: worker connection (`connect`, time limits), start screen, building and binding the screens, autosave, restart and replay (`userChange`), tabs, menus and `tapMpmb`, Sheet tab, Settings, start-up.
- Field bindings: `data-f` (input), `data-out` (formatted value), `data-rich` (MPMB rich text spans), `data-toggle` (check box), `data-items` (datalist), `data-vis` (shown as MPMB shows the field), `data-mpmb="<field>"` (a button that presses MPMB's button; shown/hidden with it), `data-opts` (drop-down from a combo box's items, plus its value when that isn't an item, such as "Unaligned"), `data-prof` (a not/proficient/expertise combo as a dot), `data-icon` (a picture button), `data-blank` (shows "Make a Selection" as empty), `data-tip` (a field's tooltip as a list, first line dropped: `Acr Prof` holds where skill proficiencies come from, shown in the Skills card; on a `<details>` it is a fold, closed or open as the user left it, `view:<charKey>` `tipsClosed`).
- `src/features.js`: reads MPMB's Class Features / Racial Traits text into features (`parse`) and spots text saved before the line-break fix (`staleClassText`, offers "Rebuild feature texts"). Also used by `test/features.test.js`.

### Builds
- `node tools/build-single.js` (version from package.json):
  - `dist-single/index.html`: the page with pdf-lib from cdnjs (what `npm start` serves).
  - `dist-single/Quillbound-Sheets.html`: one downloadable file with pdf-lib and pdf.js 3.11.174 bundled (from `pdfjs-dist`, matching the cdnjs version), fully offline. A file is never cross-origin isolated, so it uses restart and replay. The worker starts from a blob URL, or a data: URL when Chrome refuses blob workers on file:// pages.
  - `dist-site/`: the site. Adds the PWA files, `_headers`, `version.json`, pdf.js (`dist-site/pdfjs/`, `window.MPMB_PDFJS`) and the two fonts (latin and latin-ext woff2 from `@fontsource`, their @font-face inlined in place of the Google fonts links). The site contacts no other address. `_headers`: COOP/COEP, a CSP allowing only the site itself (plus 'unsafe-eval'/'unsafe-inline' for MPMB and the inline page, blob:/data: for workers and pictures), nosniff, no-referrer, DENY framing, CORP same-origin, a Permissions-Policy.
  - Escapes raw U+FFFD in pdf-lib (the Claude artifact publisher rejected it). Copies licence texts into every page (`#mpmb-licences`).
- `tools/build.sh` → `dist/` (multi-file; only used by the UI test's default).

## Features: how they work

- **Looks.** Five themes: Colorful white/dark and Printer friendly white/dark/black (OLED), plus "Match my sheet" (the default: the sheet's design from `info.SheetType`, light or dark as the device is). `html[data-look=colorful|pf][data-tone=white|dark|black]`; colour tokens at the top of index.html's CSS, components under `/* looks */`. The inline script after the CSS (`window.MPMBTheme`) applies them before the page draws, from localStorage `mpmb-theme` (`choice`, the last sheet's `look`, `color`, `seal`). Colorful takes MPMB's `Color.Theme` (strokes `--sheet`; text `--sheet-on-light`/`--sheet-on-dark`, darkened or lightened until it reads at 5.3:1 / 5:1, checked for all 11 colours) and `Color.DragonHeads` (`--seal`), watched by hidden `data-out` spans in the header, so MPMB's Color Theme options recolour the app. Picker: Settings → Look (`renderLooks`). No handwriting font, none of MPMB's or WotC's art: brush strokes, seal and corner marks are CSS shapes.
- **Settings vs Sheet tab.** Settings (gear in the top bar, `#settings`) holds the app's own things: Look, MPMB's dialogs, Install, Backups, About (`renderFacts`), Messages from MPMB (`renderLog`), Credits and licences (`renderCredits`). The Sheet tab holds what belongs to the sheet: Character, This sheet, Sheet settings, Pages, Add-on content, Sources. The App line in About shows "Quillbound Sheets 1.1" (major.minor, plus the patch when it isn't 0; no build time, the owner's wish).
- **Installable app.** `src/pwa/`: manifest, `sw.js`, icons (`icon.svg`, a d20 outline; `node tools/make-icons.js` draws the committed PNGs). Only `dist-site` gets them: build-single.js adds the manifest link (`crossorigin="use-credentials"`, or Cloudflare Access answers the manifest with its login page), theme colour, icons and `window.MPMB_SW`; `wireInstall` registers the worker and shows Settings → Install on `beforeinstallprompt`. The service worker: the page network first (6 s, then the kept copy; a login redirect is passed on and never kept), its own files precached (`OWN`), cdnjs and Google fonts cache first (for the builds that use them). The kept page keeps its COOP/COEP headers, so offline it is still isolated. Installed (standalone), the app opens the last sheet straight away (`initStart(true)`). Bump `CACHE` in sw.js only to drop old copies.
- **Updates.** An open app checks `version.json` (`{ version, build }`; `build` is compared with the page's hidden `APP_BUILD_ID`; the service worker leaves it to the network) when it comes back on screen (at most every 10 min), every 30 min while shown and 1 min after starting; a new build shows `#update-bar` (`wireUpdates`). Reload saves first and sets sessionStorage `mpmb-reload-open`, so `initStart` reopens the character.
- **Autosave.** `engine.exportState()` gives what a saved PDF would hold, as differences from the PDF as distributed (values, field and widget props, list items, scripts added with setAction, rects, calcOrder, doc info, added doc scripts), plus the page changes in order (spawn/delete/remove), which `importState()` replays before `start()` so spawned fields get the same names. Kept in IndexedDB as `char:<file name>|<size>`, saved 0.7 s after each change and when the page is hidden. The worker keeps `exportState()` until something changes (`stateNow`), so the autosave and replay share it. The autosave waits while `state.changing`.
- **Backups** (`ui-backup.js`, Settings → Backups). Asks to keep the storage (`navigator.storage.persist()`). With a folder picked (`showDirectoryPicker`, handle in IndexedDB `backupDir`) it writes the character as its PDF (the worker's `savePdf`, as Download PDF; named `<character or Unnamed character> - <sheet>.pdf`, never the sheet's own name) when the page is hidden and after 5 minutes without a change (writing takes ~5 s on the PC and MPMB waits meanwhile). After a restart Chrome may need permission again ("Allow backups again", one toast). `backup:<charKey>` keeps the last copy; a toast reminds once a day when a changed character's last copy is over 7 days old. Without folder access (Brave turns it off, Firefox and Safari lack it) the card says so (Brave detected by `navigator.brave.isBrave()`) and offers Save a copy (writes the PDF), then Send to… (`navigator.share`, where `canShare` allows) or Download: two taps, as the share sheet needs a fresh tap. The copy is dropped at the next change.
- **Spells section.** Hidden with its tab when the character has no caster in `spellOptions` (classes, feats, items), no spell sheet and no slots (`showSpells` in ui-spells.js; `state.anySlots` from app.js), or when the user hid it (Sheet → Pages, Spells section; IndexedDB `view:<charKey>` `{ hideSpells }`, deleted by Start a new character).
- **House rules** (Sheet tab, the app's own, never in the PDF): Inspiration points, a counter in place of the Inspiration dot (IndexedDB `view:<charKey>` `{ inspCount, insp }`, kept by Start a new character); MPMB's box is ticked while there is at least one point, and a box changed elsewhere wins (`showInspiration` in app.js).
- **Dice** (`ui-dice.js`, the die in the top bar, `#dice`). A roll only shows numbers, never changes the sheet. `rollOut()` (ui-core.js) makes a `data-out` number a button: `data-roll="d20"` (d20 + its text), `"dice"` (its text or `data-expr`), `"hd"` (`data-die`/`data-mod` fields), `"death"`; `data-kind` (attack, damage, save, check, init, spell), `data-what`, `data-adv` (MPMB's Adv box; its Dis box ticked = disadvantage; attacks use `Att Adv`). `markRoll` (from `apply`) disables one that isn't a number ("DC 13", empty). `diceText(node)` turns dice in texts (rich text, features, attack notes, spell rows and details) into `.dice-chip` buttons. One delegated click rolls any of them and opens the screen (scrolled to the top): the dice are small 3D solids drawn on canvases (`solid()`: faces from the dual solid; the d10 a trapezohedron; flat-shaded, numbers upright) at rest the result's face straight at you and upright, tipped back a little, in solid colour with only that face numbered, over a soft shadow: `rest`) that are thrown in from below the screen on a layer over it (`.dice-fly`), bounce across it spinning with a shadow, and land in the tray with the result face in front (0.5 s), then the total, the breakdown, Normal/Advantage/Disadvantage for a d20 (switching keeps the d20 already rolled, `spec.prev`, and rolls only the other), Roll damage after a to-hit (no critical button: roll the damage twice), Roll again, all small buttons. The builder: die pads, ±1, a box to type in (`2d8 + 1d6 - 1`). The last 50 rolls per character in IndexedDB `dice:<charKey>`. Fair dice from `crypto.getRandomValues`.
- **Magic items.** Name (with MPMB's list), attuned dot, weight (typed, as in Acrobat), the description and notes. The description shows formatted when MPMB filled it (an item it knows); for one it doesn't (homebrew typed in) it's a box to type in, and a filled one can be edited (Edit, next to the Description label). Description and Notes (`Extra.Magic Item Note N`, the user's own line, never filled by MPMB) are labelled, as on a homebrew item both start empty and looked alike. Read-only fields stay read-only.
- **Menus.** `app.popUpMenuEx` can't wait for a tap, so the worker's `tap` runs a button with every menu answered "nothing" (the menu comes back to the app), then again with the user's choice queued (`engine.queueMenu`). The Equipment menu's location column is `location2`. Every MPMB menu goes through `getMenu()`, which reads the menu first and does nothing on "nothing", so the first run has no effect.
- **Companion pages.** The PDF as distributed has one (`P4.AScomp.`); the worker's `pageList` gives each page's prefix and the app builds one set of cards per page. With no companion page the band and tab are hidden (Sheet → Pages → Change adds one). Picking a creature in `Comp.Race` makes MPMB fill the page; its Options button (`Companion.Options`) has familiars, visible sections, add/remove page; Long rest is `Comp.Heal`; a skill dot presses MPMB's skill name button (none → proficient → expertise). The worker's `addPage` runs `DoTemplate(key, "Add")`.
- **Wild Shape pages.** None in the PDF as distributed. The band and tab show once there is a `WSfront` page or MPMB has given the character Wild Shape (`Wildshapes.Info.KnownForms` set). Per page: the details (copies of `Wildshapes.Info.*` by Calculate) and four shapes, each filled by MPMB from `Wildshape.Race.N`. The Options button (`Wildshapes.Settings`) adds shapes from the beasts the character can take, removes them, recalculates, adds/removes pages.
- **Notes pages.** One pair of columns per `ASnotes` page with `Notes.Options` (lines, add a page, remove this one); "Add a notes page" when there's none. The overflow page's `MoreProficiencies` shows in the Proficiencies card when it has text or the overflow page is shown.
- **Adventurers League.** Sheet settings → Adventurers League runs MPMB's menu (`MakeAdventureLeagueMenu`/`AdventureLeagueOptions`): fixed HP, DCI, Faction/Rank/Renown (Background card), fixed carrying capacity, logsheet pages, all on/off. Picking a faction makes MPMB set the Symbol picture and the rank list. Logsheet pages (`ALlog`) get the Adventure log band and Log tab: per page `AdvLog.Options` (add/remove page, generate next entry, date format) and seven entries (`AdvLog.N.*`: date, session, adventure, DM, XP/gold/downtime/renown/magic items as start + gain = total, notes), each with its menu (`Button.AdvLog.N`: move, insert, delete, clear). Used entries plus the first empty one show. MPMB's Insert clears the first entry's typed start.
- **Pictures.** MPMB's picture buttons (`Portrait`, `Symbol`, `Comp.img.Portrait` per companion page) are button icons (/MK /I, a form XObject). Tapping one runs MPMB's picture menu (`MakeIconMenu_IconOptions`). "Set any image/pdf file as …" calls `buttonImportIcon()`: without a picture queued it returns 1 and the worker's `tap` returns `iconWanted`; the app asks for an image (`pickPicture`: the file picker straight away while the tap still counts, else `#picpick`), makes it at most 1600 px (JPEG, or PNG with transparency) and taps again with `icon` (`engine.queueIcon`). Faction, class and season icons are copies of MPMB's hidden `SaveIMG.*` buttons; "Empty" is `SaveIMG.EmptyIcon`. A button's snapshot has `icon`: `own:<name>` (its icon in the PDF), `fld:<name>` (copied) or `img:<id>` (picked; kept in widget props, so in the autosave). The app shows a picked picture as it is; otherwise the worker's `iconImage` cuts the icon out of the PDF as a one-page PDF (`MPMBWriter.iconPdf`, fitted by `iconFit`) and pdf.js draws it (`intent: 'print'`, which also draws in a background tab). Pictures added in Acrobat show in the app (Acrobat stores them inside MPMB's icon drawings). The writer embeds picked pictures and gives every picture button an appearance (centred, in proportion: Acrobat's default fit).
- **Modifiers card** (shown with MPMB's modifier fields): MPMB's switches (Jack of All Trades, Remarkable Athlete, Proficiency dice, Players make all rolls; `MOD_SWITCHES`), armour and shield weight, per attack to hit +, damage +, damage die, weight. The companion page has its initiative bonus (always shown), per-attack modifiers and its own Modifiers card.
- **Import from another sheet** (MPMB's Direct Import): two hidden same-origin iframes (`ui-import.js`), each sheet in its own realm; see Acrobat fidelity. "Start a new character" is MPMB's Reset: the app reopens the PDF as distributed and keeps add-on content.
- **Credits and licences** (`#credits`): "not made, endorsed or supported by Wizards of the Coast or MPMB"; the open sheet's own SRD statement (MPMB's `licenseSRD`, read by the worker's `open` as `info.srd`: SRD 5.2.1 on 2024 sheets, 5.1 on 2014; a general CC BY 4.0 line before a sheet is open); MPMB's GPL-3.0 credit; the app's licence (GPL-3.0-or-later, `LICENSE`, with a link to the source); pdf-lib (MIT), PDF.js (Apache 2.0), Alegreya SC/Sans (OFL 1.1). A new bundled library or font needs a line in the card and in `LICENCES` (build-single.js).

## MPMB's dialogs

Shown to the user in every build, two ways:
- **MPMB waits** (cross-origin isolated page: the site, `npm start`). `engine.interactive(fn)` turns it on. `app.execDialog` without a queued or standing answer runs as Acrobat runs it: initialize, then a loop of `fn({ kind: 'dialog', id, desc (first time only), values, lists, enabled, shown, red, focus })` → reply `{ set, pick, press }`; a pressed element runs its handler; OK runs the `ok` handler, `validate` (false keeps it open), `commit`; Cancel ends with "cancel"; Other runs the `other` handler (which ends the dialog itself) or ends with "other"; `destroy` always. Yes/No questions outside `tap` go to `fn({ kind: 'question' })` too. In the worker `fn` is `ask()`: it posts the request and blocks in `Atomics.wait` on a SharedArrayBuffer the page sent with the `channel` op; the page writes the reply there as JSON (`answerAsk` in app.js). Only for `USER_OPS`; never while opening or for the app's own probes. The stuck-timer pauses while the user answers. Needs `crossOriginIsolated`: COOP `same-origin` + COEP `credentialless` (sent by `test/serve.js` and `_headers`).
- **Restart and replay** (everywhere else: a downloaded file, an artifact; or chosen in Settings). `replay.js`: a change runs with `engine.stopForUser(true)`; a dialog or question nobody can answer stops the run (`STOP` is thrown out of MPMB's code and isn't logged) and stays open in that copy (`engine.takeStopped()`: `request()`/`step(reply)`/`finish()`, its handlers still work). The user answers; a fresh copy starts from the state before the change (`exportState`/`importState`) and runs the change again with the answers queued (`engine.setReplay`, untouched by `clearQueues`). One restart per answered dialog (~0.1 s on the PC, ~0.2 s on the test phone). In the app, every `USER_OPS` request goes through `userChange`: the worker's `run` op; a stop returns the dialog's first request and the state from before; `mpmbDialog` draws it and each reply goes to `stoppedStep`; then `freshCopy` (the spare worker from `makeSpare`, given the model as JSON, `modelJSON` from the live worker, and the PDF bytes with `prepare`) starts from that state (`startFrom`) and gets `run` again with all answers; when it finishes it replaces the live worker and the screen re-reads every watched field. A new spare is made in the background. `onIdle` (close a dialog its handlers ended) is skipped while changing.
- **The switch**: Settings → MPMB's dialogs ("MPMB waits" or "Restart and replay", kept as the backup). localStorage `mpmb-dialogs` = `replay`; `canAsk()` in app.js reads it; changing it saves and reopens the character on a new worker. Without isolation only replay is possible (radios disabled).
- **The renderer** (`mpmbDialog`, `#mdlg`): views and clusters as stacked groups (rows wrap), static text, text boxes (one loaded with a list is a drop-down), popups, list boxes and tree lists, check boxes, radios by `group_id`, buttons, and OK/Cancel/Other as the footer. After a tap the dialog blocks taps at once but dims only when MPMB takes over 0.35 s. After OK/Cancel/Other it stays on screen until MPMB is done (`idle()`; `userChange` calls it at the end) or the next dialog replaces it, closing by itself after 8 s otherwise: closing at once showed the page between two dialogs. MPMB's source marks at the end of list items (Unicode superscript, "Paladin ˢʳᵈ'²⁴") show as a small-caps label (`splitSource`; drop-downs "Paladin (SRD'24)"), as the app's fonts lack those characters; the name sent back to MPMB is unchanged.
- Requests that aren't a person's change (opening, content and sources, the app's own probes such as `spellOptions`/`classOptions`) still answer dialogs with their defaults or the app's queued steps. The worker answers MPMB's EXPERIENCE POINTS DIALOG "not now" (a standing answer); the app shows Level up instead (the class screen with the levels added to the first class).
- The Sheet tab's Sheet settings card (Weight, Unit system, Text options, Automation) needs a way to show dialogs and says so otherwise.

## Build and test

Put an MPMB 2024 sheet PDF at `test/sheet.pdf` (gitignored; never commit it, never delete or overwrite it), then `npm install`. Use the npm scripts: `npm test`, `npm run test:ui`, `npm run build`.

- `npm start`: builds `dist-single` and serves it at http://localhost:8123 (no caching, cross-origin isolated; `NOISOLATE=1` serves it like a non-isolated host).
- `npm test`: every test below except `ui.test.js`, in order (`loader.test.js` first: it writes `test/model.json`, which the others need; `import.test.js` after `writer.test.js`).

| Test | Checks |
| --- | --- |
| `loader` | reads the sheet, writes `test/model.json` |
| `engine` | MPMB in a Node `vm` realm, the self-test |
| `content [file.js]` | add-on content file, sources, a pasted script, restore into a fresh realm, remove (first `.js` in `resources/`, gitignored, the owner's own files; skips when none) |
| `spells` | Wizard 3 choices, spell sheet, prepared-only lists, row taps, regenerate, remove |
| `menus` | Elf lineage menu, Set Max HP, long rest |

## Sheet types and versions

MPMB's code runs unchanged on the 2014 sheets (v14.1.2: Colorful A4/Letter, Printer Friendly, Printer Friendly Redesign). The differences are in the fields, so **the app must never assume one sheet's layout**:
- Line counts differ (MPMB's `FieldNumbers`): Colorful A4 has 6 attacks, 8 languages/tools, 46/42 gear lines; Letter and Printer Friendly 5 attacks, 6 languages; Printer Friendly 54/36 gear lines and 17 companion gear lines. The worker counts them from the fields (`rowCounts`, returned by `open`); `rows(key, n)` in ui-core.js shows at most that many.
- A field the sheet doesn't have is left out: `absent()` in app.js marks its wrapper (`.f`, `.tg`, `.stat`, `.ad-wrap`) `data-absent` (`display: none`). Printer Friendly sheets (2024 too) have no Adv/Dis boxes, no conditions, no "Reaction used", no Attacks per Action.
- Conditions: 2024 Colorful `Condition.<Name>` + `Condition.Exhaustion`; 2014 Colorful `Extra.Condition 1..14` (2014 order, no Surprised) + `Extra.Exhaustion Level 1..6` (MPMB's ConditionSet); Printer Friendly none (the card hides).
- Wild Shapes: 2024 `Wildshapes.Info.KnownForms`/`TempHP`; 2014 `Wildshapes.Info.Uses`. Shape skills: Colorful `Text.Wildshape.N.Skills.X.Name`/`.Prof` (a combo MPMB cycles) + `Wildshape.N.Skills.X`; Printer Friendly (both years) `Wildshape.N.Skills.X.Prof`/`.Exp` check boxes + `.Mod`. The app binds both sets.
- 2014 names: "High Elf" (no Elf lineage menu), a Racial Bonus column in Ability Scores, 25 doc scripts (2024: 27).
- MPMB fills a wild shape only when all six ability scores are set (as in Acrobat).

## Acrobat fidelity: lessons learned (keep these true)

The stories behind these are in `docs/history.md`.

- **MPMB changes built-in prototypes.** `Array.prototype.find` is replaced (returns an index, takes a regex) and enumerable methods are added to `Array.prototype`. Engine code must never use `Array#find` or `for…in` over arrays. pdf-lib must run before MPMB's scripts are loaded, or in another realm.
- Document-level scripts run in name-tree order with the global `event` set to a Doc/Open event (`target` = the doc). Doc properties and methods are globals (`tDoc = this`).
- **A script setting `field.value` fires that field's Validate event before storing**, then recalculates (MPMB relies on it, e.g. `Value("Character Level", …)` → `levelFieldVal`).
- **A value a Calculate script changes is validated before it is stored.** MPMB parks a field's new text in `field.setVal`; the Calculate puts it in and the Validate deletes `setVal` (`doDropDownValCalcWithChoices` on Race, feats, magic items).
- `isBoxChecked()` returns **1/0 numbers** (MPMB compares `=== 1`). **`checkThisBox(n, 0)` unchecks**: any false-ish value (MPMB's `SetProf("advantage")` passes 0 for "neither", e.g. in `ConditionSet(true)` during Reset and the import).
- Text and combo box `.value` returns a Number when the text is numeric.
- **Line breaks in text fields are stored as CR (`\r`)**: Acrobat converts LF and CRLF to CR, and MPMB finds a class feature's section by its CR-separated lines.
- Feature headings are `#◆ Name# (source) #[usage]# rest`. A short feature has its whole description in `rest`, often in plain brackets (`[Adv on Initiative]`, `Scholar: Arcana [Expertise in Arcana]`). When a usage changes on a level up, MPMB replaces the whole heading line and drops `rest` (as Acrobat does: not a sign of old text).
- **Saved PDFs need appearance streams.** Acrobat keeps a field's formatted look only there, and redraws (NeedAppearances) before MPMB's scripts load, so MPMB's Format scripts never run. The writer draws the changed fields itself (`src/appearance.js`) from the engine's Format run (`engine.appearanceData`, passed by the worker's `savePdf` as `state.look` with MPMB's rich-text line spacing `state.lookLineHeight`): the field's DA font from /DR (bold spans in the bold version, e.g. `SegoePrint,Bold`), Acrobat's fitted size for size 0 ((height − 4) / 1.35), alignment, word wrap, colours. None of the sheet's fonts has ◆, so it's drawn as a shape; other characters outside WinAnsi come from the embedded TrueType font's cmap when it has them, else "?". Confirmed in Acrobat. The engine skips a `zzMPMBSheetApp` script from PDFs saved by an early build, and the writer removes it.
- A font MPMB sets that /DR lacks (Text Options: SegoeUI-Semibold or a custom name): the writer adds it to /DR as Acrobat does (not embedded, widths and descriptor copied from the nearest font there, else a plain Type1 name).
- MPMB needs SpiderMonkey's `toSource()` (54 uses) to store state in fields; polyfilled in engine.js.
- MPMB keeps state in hidden fields and in `submitName`/`userName` (HP Max's submitName `"0,0,0,nothing"` means not automatic). Field objects are cached per name; MPMB sets expando properties on them (`remVal`, `setVal`, `mpmbRtFormat`).
- Calculate passes run all `C` scripts in `/CO` order; MPMB batches with `calcStop()`/`calcCont()` (`tDoc.calculate`, `tDoc.delay`). `/CO` contains 57 stale parent references; the loader keeps only fields with a `C` script.
- **MPMB restarts calculations from a timer**: `calcStop()` queues `calcCont()` with `app.setTimeOut`, and only engine actions (`engine.action`, `press`, `commit`, bookmarks) run pending timeouts. Run MPMB functions that change the sheet with `engine.action`, not `evalExpr`.
- Rich text: the Format event (`formatRichText`) turns MPMB's markup into `event.richValue` spans; the app renders them (bold, MPMB purple → accent colour). A Calculate that sets `event.richValue` sets the value to the spans' text.
- JavaScript streams without a byte-order mark are UTF-8 (strict decode), falling back to PDFDocEncoding.
- **Long text values** (a saved add-on content file, `User_Imported_Files.Stringified`, is over 1 MB): pdf-lib's `decodeText()` overflows the stack, so the loader's `textOf` decodes them in pieces.
- Only a list box keeps an array value; any other field stores an array as text (`a,b`). MPMB writes arrays into `Template.extras.*` when removing pages and reads them back with `split()`.
- **Combo boxes**: items can share an export value (Size Category: Medium and Small are both "1"); Acrobat keeps the picked index (`/I`): the engine keeps it in `props.valueIndex` when MPMB sets `currentValueIndices`, the writer writes `/I`, the loader reads it. **Picking an item sends a keystroke with `willCommit` false first** (`change` = the item's name, `changeEx` = its export value), then the commit; MPMB's faction box (`SetFactionSymbol`) reads only `changeEx`.
- `engine.commit` runs the widget's On Focus and On Blur scripts around Keystroke/Validate/Calculate, as Acrobat does when you enter and leave a field (gear lines set their weight in On Blur).
- MPMB sorts menus with `localeCompare` and expects Acrobat's order: a leading space first, a leading no-break space last (Weapon Mastery). The engine's `localeCompare` does that; the browser's collation ignores both.
- **Dialogs**: `store()` follows Acrobat per element type: an `edit_text` loaded with a list object is a drop-down whose `store()` gives the chosen name as **text** (MPMB's spell pickers rely on it); list boxes give a fresh copy of their object. `insertEntryInList`/`removeAllEntriesFromList` change the list. Every text box reads back "" (check boxes and radios false) even when nothing was loaded; the Ability Scores dialog only loads non-zero boxes and does Number() on all. **Radios are exclusive per `group_id`**, also when a handler loads one. **Pressing OK runs the `ok` handler first**, then validate and commit, also for queued answers (MPMB's spell dialog stores picks only in `ok`, `saveIt`, and has no commit). `dialog.end("ok")` from a handler doesn't run `commit`. MPMB puts a second OK/Cancel row at `alignment: "align_offscreen"` (so Esc closes it); the renderer leaves it out. List items are ordered by the size of their number (MPMB numbers them -1, -2, …), then as listed. A dialog that only shows text (a read-only multi-line `edit_text`, e.g. `ShowDialog`) is auto-closed; its text is kept on the dialog log entry (`text`) and the app shows it in a panel. Standing answers (`engine.setStandingAnswer`) apply every time a dialog opens unless an answer is queued.
- **Yes/No questions** (`app.alert` nType 2/3) are answered Yes, except in the worker's `tap`: there the engine answers No and keeps the question (`askQuestions`/`takeQuestion`), the app asks, and on Yes taps again with the answer queued (`queueAnswer`). MPMB's confirmations in buttons and bookmarks come before any change, so the No run changes nothing. Questions raised while typing in a field are asked through `engine.interactive` on an isolated page, answered Yes otherwise.
- Chrome can deliver a `<dialog>`'s close event late; the Yes/No box and menus answer from their buttons and ignore a close event while the dialog is open again.
- **Spells.** By kind of caster: spellbook (typeSp "book", Wizard: selectSp is the book, selectPrep from it), whole class list ("list", Cleric/Paladin: only selectPrep; MPMB takes any selectSp, even [], as a spellbook, so spells.js deletes it), known ("known": selectSp). The app saves typeList 3 ("Prepared spells only") for casters that prepare, 2 for known casters. A spellbook over 20 spells lives in `selectSp` (the first 20) and `selectSpSB` (the rest); `options()` returns both. Bonus spells (feats, species traits, magic items such as Magic Initiate): one slot per spell in MPMB's dialog (`namesBo`, `listBo[i]`, `selectBo`, `nmbrBo`); `options()` returns them as `bonus`, `choose()` hands the picks to MPMB's dialog by the names it lists (`Bo01`…) so MPMB works out their first column; generating the list runs MPMB's spell dialogs again and `choose()` answers them as loaded. A row's state lives in its `spells.check.N` text field (`checkbox`/`checkedbox`, `oncelr`/`oncelr_used`, `markedbox`, `atwill`…); `spells.checkbox.N` is a push button that toggles it or opens the row menu. MPMB's Glossary option (its spell list dialog, `Glos`; MPMB forgets it when the sheet closes, so the app passes it each time: `choose(engine, picks, { glossary })`) adds a picture (`spellsgloss.Image`) to the spell sheet page; `sheet()` returns its field as `glossary`, and the app keeps the option as the list has it. The Spells tab shows the glossary's abbreviations as its own text instead (`GLOSSARY` in ui-spells.js, folded under the list); the picture didn't fit a phone. Spell names end with marks: ® (`SpellRitualTag`; "(R)" without unicode) for a ritual, ◉ (`SpellReqLosTag`) when the target must be seen; the Spells tab shows tags instead ("Ritual", "Needs sight"; `spellMarks` in ui-spells.js).
- MPMB hides all page-1 spell slot boxes when the slot area is off (`SpellSlotsRemember` = `[false,false]`); the app shows boxes by count with MPMB's mapping (1: mid; 2: top1+bottom1; 3: top2.1+top2.2+bottom1; 4: top2.1+top2.2+bottom2.1+bottom2.2).
- MPMB's ammunition Reset redraws the boxes for the current amount; it doesn't refill. On this sheet the tick boxes for arrows stay hidden, so "Use one" lowers the amount.
- MPMB's modifier ("blue text") fields are hidden until MPMB shows them (Skills → Options → Show fields to modify skill calculations); `data-vis` follows that.
- The distributed PDF has some dropdowns empty (magic items: 1 entry); the worker runs Source Material → Apply (`content.restore`) at every open so MPMB fills them. A saved PDF holds the dropdown items MPMB set, but the app starts from the pristine PDF, so after restoring content MPMB must rebuild them (`resourceDecisionDialog(false, false, true)`).
- Wild Shapes page: a skill dot (`ToggleSkillProf`) only changes the mark and colour; the number isn't recalculated, so the app lets the user type it. After a level up the shapes keep old values (temp HP) until Options → Re-calculate.
- **Direct Import needs two documents at once**: `DirectImport` opens the other sheet with `app.openDoc` and reads its fields and MPMB globals (`docFrom.CurrentVars`, `docFrom.What(...)`, `docFrom.isTemplVis(...)`) while it changes this one. The engine's `opts.openDoc` returns another engine's global (each sheet in its own realm; in the app two hidden iframes, as a worker has one realm). MPMB checks `docFrom.toString() === "[object Doc]"` and `docFrom.info.title` (lower case: Acrobat's info answers standard keys in lower case too). The import runs `ResetAll`, re-applies attacks before classes (a cantrip's ability stays empty: its final `ReCalcWeapons(false)` keeps the field), doesn't copy limited-feature uses, and re-adds the default automation (`CurrentEvals`) only at the next opening; the app reopens the result, as Acrobat would.

### MPMB bugs (same in Acrobat; not reported to Joost yet)
- **Hang:** `AddToNotes` (Functions2) leaves its search of the Notes pages with `i = noteFlds.length` (2, the columns) instead of the page count. Removing a feature whose text is on the 3rd+ Notes page loops forever. Safety net: every worker request has a time limit (`SLOW_OPS`/`LIMIT_S` in app.js); past it the app stops the worker, reopens from the autosave and offers "Clear out Notes pages" (`DoTemplate("ASnotes", "RemoveAll", false, true)`, after showing their text).
- A shape's passive Perception is always 10: `ApplyWildshape` reads `fldBase + "Skills.Perc"` without the dot (`fldBase` is `…Wildshape.1`). The app shows what MPMB writes.
- `format2` (logsheet gain fields, Carrying Capacity Multiplier) calls `countDecimals()` on a string, so it throws for plain numbers; Acrobat shows the unformatted value, as the app does (the error is in Messages).
- Emptying the script in `AddUserScript` calls `InitiateLists()` without re-running the imported files, so their content vanishes until reopening. `content.js` removes a pasted script with the file dialog's steps instead.

## Known gaps

- Single items in Sources: MPMB opens those selection dialogs (`resourceSelectionDialog(type)`) from buttons inside Source Selection, a dialog inside a dialog, which restart and replay can't do (in a stopped copy every further dialog is cancelled: `stopped` set in execDialog). The app's way in: `content.excludeItems`, the worker's user op `excludeItems`. The app opens the selection dialog itself (a normal user dialog in both modes) and, when `CurrentSources` changed, presses Source Selection's Apply for the user (queued, steps []). `hasStopped` keeps a stopped copy from running the slow Apply. A general fix for nested dialogs isn't built: no other dialog the user answers nests one. The selection dialogs' "List Source Abbreviations" (`bSrc`) opens a menu, which a dialog handler can't show (it does nothing). `info()` returns `excluded` (count per kind). MPMB excludes a class group when all its subclasses are.
- Not wired: XFDF import/export (deprecated in MPMB), importing user-defined icons. Text Options changes the PDF's fonts and lines, which the app's own look ignores.
- **No empty field nodes in a saved PDF.** A node without kids and without a widget is a broken field to Acrobat, and MPMB's scripts stop working there (bookmarks and buttons do nothing), while the app's engine doesn't mind. The writer's `dropField` removes parents left empty when a page is deleted; `test/writer.test.js` adds and removes a companion page and checks.
- The writer skips overlay spawns; MPMB never makes one (all its `spawn` calls pass bOverlay false).
- The rest is in the design doc's "Still to do".
