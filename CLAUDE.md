# MPMB Sheet App: project notes for Claude Code

> **How changes reach the owner: `git push` to `master`. Do NOT republish the Claude artifact.**
> Cloudflare Pages rebuilds https://mpmb-sheet-app.pages.dev/ on every push to `master`, and that is where the owner tests. The old test-build artifact (ARTIFACT) is retired: republishing it from a new session makes Claude read the whole live page first (~575 KB, ~270k tokens, ~10% of the owner's session limit), which is the cost Cloudflare was set up to avoid. Never publish, read or update that artifact unless the owner asks for it in that session. At the end of a change: run the tests, commit, push (ask the owner before pushing if he hasn't said to), and tell him the site redeploys from the push.

A phone-first web app (the owner's project) that opens an **MPMB 2024 (5.5e) character sheet PDF** and runs MPMB's own scripts in a stand-in for Adobe Acrobat. Users can play and build characters on a phone or tablet, with all D&D logic coming from MPMB's code inside their PDF.

- Design doc (decisions, milestones, risks): https://claude.ai/code/artifact/DESIGN-DOC
- Old test build (retired 2026-10-20, last version 53): private Claude artifact https://claude.ai/artifact/ARTIFACT. Don't republish it unless the owner asks (see the note at the top); `dist-single/index.html` is what it was published from.
- Code: private GitHub repo https://github.com/OWNER/mpmb-sheet-app (branch `master`, pushed with the `gh` login of the owner's account OWNER). Hosting with real dialogs: Cloudflare Pages from that repo (build `node tools/build-single.js 0.2`, output `dist-site`, which holds the full page and `_headers` with COOP/COEP), behind Cloudflare Access so only the owner can open it. Live since 2026-10-20 at https://mpmb-sheet-app.pages.dev/ (cross-origin isolated, so MPMB waits for dialogs; every push to `master` redeploys). Access app "MPMB Sheet App" (team TEAM) needs the bare hostname `mpmb-sheet-app.pages.dev` as well as `*.mpmb-sheet-app.pages.dev`, or the login says "Unable to find your Access application". The Cloudflare connector's tools can't manage Pages or Access: use the dashboard.
- Test devices: the phone (6.3", 1220×2656, about 393×852 CSS px at 3.1×) and the tablet (10.9", 1440×2304, about 800×1280 at 1.8×). Chrome on Android.

## Decisions (settled with the owner)

| Topic | Decision |
| --- | --- |
| Look | The app's own layout, phone first (PDF pages are unreadable on phones) |
| Navigation | One scrolling page per screen size + bottom tab bar that jumps to sections and follows the scroll |
| Layout | 1 column phone portrait, 2 columns phone landscape / tablet portrait, 3 columns tablet landscape |
| Save file | The MPMB PDF itself (+ autosave inside the app). Both built; a PDF saved by the app works completely in the owner's real Acrobat (checked 2026-10-19, version 40) |
| Platform | Web app installed from Chrome; app stores later, if ever |
| Scope | Play **and** build characters |
| Rules | 2024 sheets first; the 2014 (v14) sheets work too (2026-10-20); later MPMB versions must keep working |
| Looks | Five themes after MPMB's Colorful and Printer Friendly sheets + "Match my sheet"; no handwriting font; sheet art recreated in CSS, never shipped |

## Files

- `src/loader.js`: reads the PDF with pdf-lib. Outputs a plain "sheet model": document scripts (name-tree order), fields, widgets, field scripts (K/F/V/C) and widget scripts (A/D/U/E/X/Fo/Bl), calculation order, templates, info dictionary, bookmarks.
- `src/engine.js`: the Acrobat stand-in. Field objects, events, `app`/`util`/doc APIs, AForm helpers, `toSource()`, templates/pages, logs.
- `src/worker.js`: one sheet per Web Worker. Its own code sits in an IIFE because the global scope belongs to MPMB.
- `src/app.js`, `src/index.html`: the screens. The page's scripts load in index.html's order (the single-file build joins them in that order, app.js last, which starts the app): `src/features.js`, then `src/ui-core.js` (shared helpers `$`, `$$`, `el`, the app's lists and `state`, put in `window.MPMBUI`), then one file per area, each an IIFE that takes what it needs from `MPMBUI` and adds its own functions to it (calls into other files go through small `U.name(...)` forwarders, so their load order doesn't matter): `ui-dialog.js` (`mpmbDialog`), `ui-pages.js` (companion, wild shape, notes and logsheet pages), `ui-classes.js` (class and ability score screens), `ui-pictures.js`, `ui-spells.js`, `ui-content.js` (add-on content and sources), `ui-import.js` (Import from another sheet), `ui-backup.js` (Settings → Backups); then `app.js` (worker connection, start screen, building and binding the screens, autosave, restart and replay, tabs, menus and `tapMpmb`, Sheet tab, start-up). A new page script needs a `<script src>` line in index.html (the builds pick it up from there) and a `cp` in tools/build.sh. Fields are bound with `data-f` (input), `data-out` (formatted value), `data-rich` (MPMB rich text spans), `data-toggle` (check box), `data-items` (datalist).
- Looks (themes, 2026-10-19): five, after MPMB's two sheet designs: Colorful white/dark and Printer friendly white/dark/black (OLED), plus "Match my sheet" (default: the sheet's design from `info.SheetType`, light or dark as the device is). `html[data-look=colorful|pf][data-tone=white|dark|black]`; colour tokens at the top of index.html's CSS, components under `/* looks */`. The inline script after the CSS (`window.MPMBTheme`) applies them before the page draws, from localStorage `mpmb-theme` (`choice`, the last sheet's `look`, `color`, `seal`). Colorful takes MPMB's `Color.Theme` (strokes: `--sheet`; text: `--sheet-on-light` / `--sheet-on-dark`, the colour darkened or lightened until it reads at 5.3:1 / 5:1, checked for all 11 colours) and `Color.DragonHeads` (`--seal`, the red seal and slashes), watched by hidden `data-out` spans in the header, so MPMB's Set Pages Layout → Color Theme options recolours the app. Picker: Settings (gear button in the top bar, `#settings` panel) → Look (`renderLooks` in app.js). The Settings panel (2026-10-20) holds the app's own things: Look, About (`renderFacts`: app build, dialogs mode, file, sheet, timings, screen) and Messages from MPMB (`renderLog`); the Sheet tab keeps what belongs to the sheet (Character, This sheet, Sheet settings, Pages, Add-on content, Sources). No handwriting font and none of MPMB's or WotC's art: brush strokes, seal and corner marks are CSS shapes.
- Installable app (2026-10-20): `src/pwa/` holds the manifest, `sw.js` and icons (`icon.svg`, a plain d20 outline; `node tools/make-icons.js` draws the PNGs, which are committed). Only `dist-site` gets them: build-single.js adds the manifest link (`crossorigin="use-credentials"`, or Cloudflare Access answers the manifest with its login page), theme colour, icons and `window.MPMB_SW`; `wireInstall` in app.js registers the worker and shows Settings → Install when Chrome offers it (`beforeinstallprompt`). The service worker: the page network first (6 s, then the kept copy; a login redirect is passed on and never kept), cdnjs and Google fonts cache first. The kept page keeps its COOP/COEP headers, so offline it is still cross-origin isolated (checked). Installed (standalone), the app opens the last sheet straight away (`initStart(true)`). Bump `CACHE` in sw.js only to drop old copies; updates arrive anyway (network first).
- The site contacts no other address (2026-10-20): build-single.js copies pdf.js (`dist-site/pdfjs/`, `window.MPMB_PDFJS` read by ui-pictures.js) and the two fonts (latin and latin-ext woff2 from the `@fontsource` packages, OFL; their @font-face inlined in place of the Google fonts links) into the site, and adds them to the service worker's precache list (OWN). `_headers` has a Content-Security-Policy that allows only the site itself (plus 'unsafe-eval' and 'unsafe-inline' for MPMB and the inline page, blob:/data: for the workers and pictures), nosniff, no-referrer, DENY framing, CORP same-origin and a Permissions-Policy. test/serve.js sends a folder's `_headers` too, and with `SERVE_SHEET=1` serves test/sheet.pdf at `/__sheet.pdf` (the CSP blocks fetching it from another port); the launch.json "site" config sets it.
- Backups (2026-10-20, `src/ui-backup.js`, Settings → Backups): asks Chrome to keep the storage (`navigator.storage.persist()`, shown in the card) and, with a folder picked (`showDirectoryPicker`, handle kept in IndexedDB `backupDir`), writes the character as its PDF (the worker's `savePdf`, the same file as Download PDF, named `<character or Unnamed character> - <sheet>.pdf`, never the sheet's own name) when the page is hidden and after 5 minutes without a change. Writing takes ~5 s on the PC (MPMB waits meanwhile), hence not after every change. After a restart Chrome may need permission again: the card shows Allow backups again (a toast says so once). `backup:<charKey>` keeps the last copy (folder or download); a toast reminds once a day when a changed character's last copy is over 7 days old. Checked with the origin private folder standing in for the picker.
- Dialog mode (2026-10-20): Settings → MPMB's dialogs picks "MPMB waits" (Atomics, needs isolation) or "Restart and replay" (the backup, the owner wants it kept). localStorage `mpmb-dialogs` = `replay`; `canAsk()` in app.js reads it, and changing it saves and reopens the character on a new worker connection. Without isolation only replay is possible (the radios are disabled).
- `src/features.js`: reads MPMB's Class Features / Racial Traits text into features (`parse`) and spots text saved before the line-break fix (`staleClassText`). Used by the app (inlined before app.js in the builds) and `test/features.test.js`.
- `src/selftest.js`: builds an Elf Wizard 3 and checks 19 results. Used by the Node tests (`test/engine.test.js` and others); the app's Self-test card was removed on 2026-10-19 (the owner: unnecessary).
- `src/spells.js`: spells. `options()` runs MPMB's `AskUserSpellSheet` once with the dialogs' data captured (lists, counts, picks) and cancels at the last dialog; `choose()` writes the picks where those dialogs keep them (`CurrentSpells[caster].selectCa/selectSp/selectPrep/typeList`) and runs MPMB's `GenerateSpellSheet`; `sheet()` reads the spawned SSfront/SSmore pages back as rows; `tapRow()` presses a row's first-column button (prepared / used).
- Menus: `app.popUpMenuEx` can't wait for a tap, so the worker's `tap` op runs a button with every menu answered "nothing" (the menu comes back to the app), then runs it again with the user's choice queued (`engine.queueMenu`). Every MPMB menu goes through `getMenu()`, which reads the menu first and does nothing on "nothing", so the first run has no effect. Buttons in the page use `data-mpmb="<field name>"` and show/hide as MPMB shows/hides the field.
- `src/classes.js`: MPMB's Class Selection dialog (`SelectClass`): `options()` reads its lists and rows (captured, then cancelled); `apply()` clears every row, then per row picks class, subclass and level in the dialog's drop-downs (pressing their handlers) and presses Apply.
- `src/abilities.js`: MPMB's Ability Scores dialog: `options()` reads `CurrentStats.cols` and MPMB's explanation (the ability tooltip), `preview()` uses MPMB's `getAbilityScoreTotals(i, dialogStore)` and `ASCalcPointBuy`, `apply()` types each changed box and presses Apply.
- `src/appearance.js`: how text fields, combo boxes and changed button captions look in the saved PDF (appearance streams), used by the writer; see the Acrobat fidelity notes.
- `src/writer.js`: writes `engine.exportState()` into the sheet's own PDF with pdf-lib: replays page changes (a spawned template page is a copy of the template page, `/Type` set to `/Page`, its fields renamed `P<page>.<template>.<name>` under new parent nodes), then values, field/widget changes (flags, TU/TM, Opt, DA, MK colours/caption/icon, BS, Rect, scripts as JavaScript actions), /CO, info, added doc scripts, and sets NeedAppearances. In the artifact the download goes through the `downloads` capability.
- Companion pages: the PDF as distributed has one (`P4.AScomp.`); the worker's `pageList` gives each page's prefix and the app builds one set of cards per page (`buildCompanion` / `syncCompanions` in app.js), rebuilt when the pages change. Picking a creature in `Comp.Race` makes MPMB fill the page; its Options button (`Companion.Options`) has familiars, visible sections, and add/remove page; Long rest is MPMB's `Comp.Heal`; a skill dot presses MPMB's skill name button (cycles none → proficient → expertise). `data-opts` fills a drop-down from a combo box's items (plus its value when that isn't an item, such as "Unaligned"); `data-prof` shows a not/proficient/expertise combo as a dot. The worker's `addPage` runs `DoTemplate(key, "Add")` for the "Add a companion page" button.
- Wild Shape pages: none in the PDF as distributed. The Wild Shape band and tab show once there is a `WSfront` page or MPMB has given the character Wild Shape (`Wildshapes.Info.KnownForms` set); "Add a Wild Shapes page" is the worker's `addPage`. One set of cards per page (`buildWildShapePage` / `syncWildShapes` / `refreshWildShapes` in app.js): the page's details (copies of MPMB's `Wildshapes.Info.*` by Calculate) and four shapes, each filled by MPMB from its `Wildshape.Race.N` box (`data-blank` shows "Make a Selection" as empty). The page's Options button (`Wildshapes.Settings`) adds shapes from the beasts the character can take, removes them, recalculates, and adds/removes pages.
- MPMB's dialogs shown to the user: `engine.interactive(fn)` turns it on. `app.execDialog` without a queued or standing answer then runs as Acrobat runs it: initialize, then a loop of `fn({ kind: 'dialog', id, desc (first time only), values, lists, enabled, shown, red, focus })` → reply `{ set, pick, press }`; a pressed element runs its handler, OK runs the `ok` handler, `validate` (false keeps it open), `commit`; Cancel ends with "cancel"; Other runs the `other` handler (which ends the dialog itself) or ends with "other"; `destroy` always. Yes/No questions outside `tap` go to `fn({ kind: 'question' })` too. In the worker `fn` is `ask()`: it posts the request and blocks in `Atomics.wait` on a SharedArrayBuffer the page sent with the `channel` op; the page writes the reply as JSON there (`answerAsk` in app.js). Only for requests a person started (`ASKS_USER` in worker.js); never while opening or for the app's own probes. The page draws the dialog (`mpmbDialog` in app.js, `#mdlg`) from the description: views and clusters as stacked groups (rows wrap), static text, text boxes (a text box loaded with a list is a drop-down), popups, list boxes and tree lists, check boxes, radios by `group_id`, buttons, and the OK/Cancel/Other row as the panel footer. The stuck-timer pauses while the user answers. Needs `crossOriginIsolated` (COOP `same-origin` + COEP `credentialless`, sent by `test/serve.js`); without it there is no channel and dialogs keep their defaults, as before. The Sheet tab's Sheet settings card (Weight, Unit system, Text options, Automation) needs it and says so otherwise.
- `src/replay.js`: restart and replay, MPMB's dialogs and questions answered by the user without pausing MPMB (works in the artifact and a single file, at full speed). A change runs with `engine.stopForUser(true)`; a dialog or yes/no question nobody can answer stops the run (`STOP` is thrown out of MPMB's code and isn't logged) and stays open in that copy (`engine.takeStopped()`: `request()` / `step(reply)` / `finish()`, its handlers still work). The user answers it; a fresh copy starts from the state before the change (`exportState` / `importState`, as the autosave) and runs the change again with the answers queued (`engine.setReplay`, untouched by `clearQueues`): a replayed dialog goes through the same request/step code as a live one. One restart per answered dialog (~0.1 s on the PC, ~0.2 s on the owner's phone). `test/replay.test.js` checks each case against one copy that really waits (`engine.interactive`), field by field.
- Restart and replay in the app (2026-10-19), used whenever the page can't wait (not cross-origin isolated: the artifact, a downloaded file). Every request a person starts (`USER_OPS` in app.js, the same list in worker.js) goes through `userChange` in app.js: the worker's `run` op makes the change with stopping on; a stop returns the dialog's first request (or the question) and the state from before the change. The dialog is drawn by `mpmbDialog` and each reply goes to `stoppedStep` (MPMB's handlers run in the stopped copy). Then `freshCopy`: the spare worker (`makeSpare`: a second worker given the sheet model as JSON, `modelJSON` from the live worker, and the PDF bytes with `prepare`) starts from that state (`startFrom`, with the app's watched field names) and gets `run` again with all answers so far; when it finishes, it replaces the live worker and the screen re-reads every watched field. A new spare is made in the background. The worker keeps `exportState()` until something changes (`stateNow`, `READS` lists the requests that don't change anything), so the autosave and `run` share it. The autosave waits while `state.changing` (the live copy holds a half-made change). `onIdle` (close a dialog its handlers ended) is skipped while changing.
- Pictures (2026-10-19): MPMB's picture buttons (`Portrait`, `Symbol` on the Background page, `Comp.img.Portrait` per companion page) are button icons (/MK /I, a form XObject). Tapping one in the app runs MPMB's own picture menu (`MakeIconMenu_IconOptions`). "Set any image/pdf file as …" calls `buttonImportIcon()`: without a picture queued it returns 1 (cancelled) and the worker's `tap` returns `iconWanted`; the app asks for an image (`pickPicture`: the file picker straight away while the tap still counts as a user action, else the `#picpick` panel), makes it at most 1600 px (JPEG, or PNG with see-through parts) and taps again with `icon` (`engine.queueIcon`). Faction, class and season icons are copies of MPMB's hidden `SaveIMG.*` buttons; "Empty" is `SaveIMG.EmptyIcon` (no icon). The snapshot of a button has `icon`: `own:<name>` (its icon in the PDF), `fld:<name>` (copied) or `img:<id>` (picked; kept in widget props, so in the autosave). The app shows it (`data-icon`, `showIcon`): a picked picture as it is; otherwise the worker's `iconImage` cuts the icon out of the opened PDF as a one-page PDF of the button's size (`MPMBWriter.iconPdf`, fitted by `iconFit`) and the page draws it with pdf.js 3.11.174 from cdnjs (`intent: 'print'`, which doesn't wait for animation frames, so it also draws in a background tab). MPMB's own icons are PDF drawings and Acrobat stores an added image inside such a drawing, so pictures added in Acrobat show in the app. The writer embeds picked pictures (one icon per picture) and gives every picture button an appearance drawing its icon in proportion and centred (Acrobat's default fit), so Acrobat and other viewers show it.
- Adventurers League (2026-10-20): Sheet tab → Sheet settings → Adventurers League runs MPMB's menu (`MakeAdventureLeagueMenu` / `AdventureLeagueOptions`): fixed HP, DCI field, Faction / Faction Rank / Renown (Background card), fixed carrying capacity, logsheet pages, all on / all off. The fields show as MPMB shows them (`data-vis`). Picking a faction makes MPMB set the Symbol picture and the rank list. Logsheet pages (template `ALlog`, none in the PDF as distributed) get the Adventure log band and Log tab (`buildLogPage` / `syncLogs` / `refreshLogs` in app.js): per page MPMB's Options button (`AdvLog.Options`: add/remove page, generate next entry, date format) and seven entries (`AdvLog.N.*`: date, session, adventure, DM, XP/gold/downtime/renown/magic items as start + gain = total, notes), each with MPMB's entry menu (`Button.AdvLog.N`: move, insert, delete, clear). Used entries plus the first empty one show. MPMB's Insert clears the first entry's typed start (it moves only gains, dates and notes).
- Notes pages (2026-10-20): one pair of columns per `ASnotes` page with MPMB's Options button (`Notes.Options`: lines per column, add a page, remove this one), built from the worker's `pageList` (`syncNotes` in app.js); "Add a notes page" when there's none. The overflow page's `MoreProficiencies` (languages and tools that didn't fit) shows in the Proficiencies card when it has text or the overflow page is shown.
- Modifiers card (shown with MPMB's modifier fields): MPMB's switches (Jack of All Trades, Remarkable Athlete, Proficiency dice, Players make all rolls; `MOD_SWITCHES`), armour and shield weight, and per attack to hit +, damage +, damage die, weight. The companion page has its initiative bonus (always shown), per-attack modifiers and a Modifiers card (proficiency dice, saves, skills).
- `src/content.js`: add-on content (MPMB's "Add Extra Materials" and "Source Material" bookmarks). Runs MPMB's own dialogs with the buttons pressed for the user (`engine.queueDialog`), with the picked file queued for `util.readFileIntoStream()` (`engine.queueFile`). The app keeps the three fields that hold the content (`User_Imported_Files.Stringified`, `User Script`, `CurrentSources.Stringified`) in IndexedDB per sheet (file name + size), presets them before `start()`, and then runs `restore()` (Source Selection → Apply) to rebuild the dropdowns.

## Acrobat fidelity: lessons learned (keep these true)

- **MPMB changes built-in prototypes.** `Array.prototype.find` is replaced (it returns an index and takes a regex), and enumerable methods are added to `Array.prototype`. Engine code must never use `Array#find` or `for…in` over arrays. pdf-lib must run before MPMB's scripts are loaded, or in another realm.
- Document-level scripts run in name-tree order with the global `event` set to a Doc/Open event (`target` = the doc). Doc properties and methods are globals (`tDoc = this`).
- **A script setting `field.value` fires that field's Validate event before storing**, then recalculates. MPMB relies on this (for example `Value("Character Level", …)` → `levelFieldVal`).
- `isBoxChecked()` returns **1/0 numbers**: MPMB compares `=== 1` (saving-throw proficiency broke with booleans).
- Text and combo box `.value` returns a Number when the text is numeric.
- **Line breaks in text fields are stored as CR (`\r`)**: Acrobat converts LF (`\n`) and CRLF to CR. MPMB finds a class feature's section by its CR-separated lines; with LF left in, every new feature went in under the previous heading and the descriptions piled up at the end in reverse order. Characters saved before this fix keep the bunched text until the class is removed and added again.
- Feature headings are `#◆ Name# (source) #[usage]# rest`. A short feature has its whole description in `rest`, often in plain brackets (`[Adv on Initiative]`, `Scholar: Arcana [Expertise in Arcana]`); the app showed these as "No description." until `src/features.js`. When a usage changes on a level up, MPMB replaces the whole heading line and drops `rest` (Wild Shape's "(see 3rd page)"), as Acrobat does: not a sign of old text.
- **A PDF saved by the app showed MPMB's markup in Acrobat** ("#◆ Spellcasting#", "**Druid…**", seen by the owner 2026-10-19). Acrobat keeps the formatted look of a field only in its appearance stream. The writer used to set NeedAppearances, and Acrobat redraws before MPMB's scripts are loaded, so MPMB's Format scripts never ran; a document script that redrew the fields afterwards (`password = false`) didn't help either. Now the writer draws the changed fields itself (`src/appearance.js`) from what the engine's Format run shows (`engine.appearanceData`, passed by the worker's `savePdf` as `state.look` with MPMB's rich-text line spacing `state.lookLineHeight`) and no longer sets NeedAppearances. It uses the field's DA font from /DR (bold spans in the font's bold version, e.g. `SegoePrint,Bold`), Acrobat's fitted size for size 0 ((height − 4) / 1.35), alignment, word wrap, colours. None of the sheet's fonts has ◆ (Acrobat takes it from a system font), so it's drawn as a shape; other characters outside WinAnsi come from the embedded TrueType font's cmap when it has them, else "?". the owner confirmed in Acrobat on 2026-10-19 that this works. The engine still skips a `zzMPMBSheetApp` script from PDFs saved by that earlier build, and the writer removes it. To look at a saved PDF: `notes/sheet-serve.js` serves `/view?f=saved&p=2&s=2.5` (pdf.js draws the appearances).
- MPMB needs SpiderMonkey's `toSource()` (54 uses) to store state in fields. It's polyfilled in engine.js.
- MPMB keeps state in hidden fields and in `submitName`/`userName` (for example HP Max's submitName is `"0,0,0,nothing"`, which means not automatic).
- Field objects are cached per name; MPMB sets expando properties on them (`remVal`, `setVal`, `mpmbRtFormat`).
- Calculate passes run all `C` scripts in `/CO` order; MPMB batches with `calcStop()`/`calcCont()` (`tDoc.calculate`, `tDoc.delay`).
- Rich text fields: the Format event (`formatRichText`) turns MPMB's markup into `event.richValue` spans. The app renders these spans (bold, MPMB purple → accent colour).
- JavaScript streams without a byte-order mark are UTF-8 (strict decode), falling back to PDFDocEncoding.
- `/CO` contains 57 stale parent references; the loader keeps only fields that have a `C` script.
- Dialog `store()` follows Acrobat per element type: an `edit_text` loaded with a list object is a drop-down whose `store()` gives the chosen name as **text** (MPMB's spell pickers rely on this); list boxes give a fresh copy of their object. `insertEntryInList`/`removeAllEntriesFromList` change the list (the spell sheet order dialog fills its list this way; without them every spell sheet came out empty).
- MPMB hides all page-1 spell slot boxes when the sheet's slot area is off (`SpellSlotsRemember` = `[false,false]`); the app shows boxes by count, using MPMB's own mapping (1: mid; 2: top1+bottom1; 3: top2.1+top2.2+bottom1; 4: top2.1+top2.2+bottom2.1+bottom2.2).
- Spell picks by kind of caster: spellbook (typeSp "book", Wizard: selectSp is the book, selectPrep from it), whole class list ("list", Cleric/Paladin: only selectPrep; MPMB takes any selectSp, even [], as a spellbook and the prepare list comes out empty, so spells.js deletes it), known ("known": selectSp). The app saves with typeList 3 ("Prepared spells only") for casters that prepare, 2 for known casters, so the Spells tab shows what can be cast.
- A spellbook over 20 spells lives in two parts: `selectSp` (the first 20, MPMB's spell dialog) and `selectSpSB` (the rest, its extra spellbook dialog). `spells.options()` returns both as the chosen book; with only the first part, the next save dropped the rest and the prepared spells in it.
- A spell row's state lives in its `spells.check.N` text field (`checkbox`/`checkedbox`, `oncelr`/`oncelr_used`, `markedbox`, `atwill`…); `spells.checkbox.N` is a push button that toggles it, or opens the row menu.
- Every text box in a dialog reads back "" (check boxes and radios false) even when nothing was loaded, as in Acrobat; the Ability Scores dialog only loads non-zero boxes and does Number() on all of them.
- Standing dialog answers (`engine.setStandingAnswer`) apply every time a dialog opens unless an answer is queued. The worker answers MPMB's EXPERIENCE POINTS DIALOG "not now" (cancel); the app shows Level up instead, which opens the class screen with the levels added to the first class.
- MPMB's ammunition Reset button redraws the boxes for the current amount; it doesn't refill. On this sheet the tick boxes for arrows stay hidden, so "Use one" lowers the amount.
- Chrome can deliver a `<dialog>`'s close event late (seen in a background page: none fired until it rendered). The Yes/No box and menus answer from their buttons and ignore a close event while the dialog is open again, so a late event can't answer the next question.
- Yes/No questions (`app.alert` nType 2/3) are answered Yes, except in the worker's `tap`: there the engine answers No and keeps the question (`askQuestions`/`takeQuestion`), the app asks the user, and on Yes taps again with the answer queued (`queueAnswer`). MPMB's confirmations in buttons and bookmarks ("Remove Companion sheet… This can't be undone!") come before any change, so the No run changes nothing. Questions raised while typing in a field (feat prerequisites, "use traits from the old species") are asked through `engine.interactive` on an isolated page, and answered Yes otherwise.
- **MPMB bug (hang):** `AddToNotes` (Functions2) leaves its search of the Notes pages with `i = noteFlds.length` (2, the columns) instead of the page count. Removing a feature whose text is on the 3rd+ Notes page loops forever (Acrobat too). The app's safety net: every worker request has a time limit (`SLOW_OPS` / `LIMIT_S` in app.js); past it the app stops the worker, reopens the character from the autosave and offers "Clear out Notes pages" (`DoTemplate("ASnotes", "RemoveAll", false, true)`, after showing their text). Not reported to Joost yet.
- **MPMB restarts calculations from a timer**: `calcStop()` queues `calcCont()` with `app.setTimeOut`, and only engine actions (`engine.action`, `press`, `commit`, bookmarks) run pending timeouts. Run MPMB functions that change the sheet with `engine.action`, not `evalExpr`, or calculations stay off (a new page's calculated fields stayed empty).
- Wild Shapes page: a skill dot (`ToggleSkillProf`) only changes the mark and its colour; the number isn't recalculated (the companion page has calculations, this page doesn't), so the app lets the user type it. After a level up the shapes keep the old values (temp HP) until Options → Re-calculate, as MPMB updates them before the page's details recalculate.
- **MPMB bug:** a shape's passive Perception is always 10: `ApplyWildshape` reads `fldBase + "Skills.Perc"` without the dot (`fldBase` is `…Wildshape.1`). Same in Acrobat; the app shows what MPMB writes. Not reported to Joost yet.
- Dialog descriptions: MPMB puts a second OK/Cancel row at `alignment: "align_offscreen"` (Acrobat draws it outside the window so Esc closes the dialog); the renderer leaves those out. `dialog.end("ok")` from a handler doesn't run `commit` (MPMB's `other` handlers read `store()` themselves). List items are ordered by the size of their number (MPMB numbers them -1, -2, …), then as listed.
- **A value a Calculate script changes is validated before it is stored** (Acrobat order). MPMB parks a field's new text in `field.setVal`; the field's Calculate puts it in and its Validate deletes `setVal` (`doDropDownValCalcWithChoices`, on Race, feats, magic items). Without that Validate, `setVal` stayed and the next species, feat or magic item typed was ignored (Human after picking Infernal Tiefling).
- Combo box items can share an export value (Size Category: Medium and Small are both "1"). Acrobat keeps the picked index (`/I`): the engine keeps it in `props.valueIndex` when MPMB sets `currentValueIndices`, the writer writes `/I`, the loader reads it. Before, picking Small read back as Medium.
- **Pressing OK runs the dialog's `ok` handler first**, then validate and commit, also when the app answers a dialog with queued steps. MPMB's spell selection dialog stores the picks only in `ok` (`saveIt`) and has no commit: without it, bonus spell picks (Magic Initiate) were lost.
- Bonus spells (feats, species traits, magic items that give spells, such as Magic Initiate): MPMB's spell dialog has one slot per spell (`namesBo`, `listBo[i]`, `selectBo`, `nmbrBo`). `spells.options()` returns them as `bonus`; `choose()` hands the picks to MPMB's dialog by the names it lists (`Bo01`…), so MPMB works out which spells are bonus spells and their first column ("once per long rest"). Generating the list runs MPMB's spell dialogs again: `choose()` answers them as loaded, or restart and replay would stop there and show them.
- Only a list box keeps an array value; any other field stores an array as text (`a,b`), as Acrobat does. MPMB writes arrays into `Template.extras.*` when removing pages and reads them back with `split()`.
- MPMB sorts menus with `localeCompare` and expects Acrobat's order: a leading space first, a leading no-break space last (Weapon Mastery: " Simple…" first, "\xA0Mastery Text Only" last). The engine's `localeCompare` does that; the browser's collation ignores both.
- A dialog that only shows text (a read-only multi-line `edit_text`, e.g. MPMB's `ShowDialog`) is auto-closed, but its text is kept on the dialog log entry (`text`); the worker's `tap` returns it with the alerts and the app shows it in a panel.
- MPMB's modifier ("blue text") fields are hidden until MPMB shows them (Skills → Options → Show fields to modify skill calculations); the app's `data-vis` binding follows that.
- `engine.commit` runs the widget's On Focus and On Blur scripts around Keystroke/Validate/Calculate, as Acrobat does when you enter and leave a field (gear lines set their weight in On Blur).
- The distributed PDF has some dropdowns empty (magic items: 1 entry); the worker runs MPMB's Source Material → Apply (`content.restore`) at every open so MPMB fills them.
- Autosave: `engine.exportState()` gives what a saved PDF would hold as differences from the PDF as distributed (values, field and widget props, list items, scripts added with setAction, rects, calcOrder, doc info, added doc scripts) plus the page changes in order (spawn/delete/remove), which `importState()` replays before `start()` so spawned fields get the same names. The app keeps it in IndexedDB as `char:<file name>|<size>`, saving 0.7 s after each change and when the page is hidden.
- A saved PDF also holds the dropdown items MPMB set; the app starts from the pristine PDF, so after restoring content MPMB must rebuild them (`resourceDecisionDialog(false, false, true)`).
- **Radios in a dialog are exclusive per `group_id`**, also when a handler loads one (`dialog.load({ fAlt: true })`): Text Options' font list loads its radio and commit reads the first radio that is on. Before, "Standard font" stayed on and every font choice was dropped.
- **Picking a combo box item sends a keystroke with `willCommit` false first**, `change` = the item's name, `changeEx` = its export value, then the commit (Acrobat order). MPMB's faction box (`SetFactionSymbol`) sets the Symbol picture and the rank list only from `changeEx`.
- A font MPMB sets that the form's /DR lacks (Text Options: SegoeUI-Semibold, or a custom font name): the writer adds it to /DR as Acrobat does (not embedded, widths and descriptor copied from the nearest font there, else a plain Type1 name).
- **MPMB bug:** `format2` (gain fields on the logsheet, Carrying Capacity Multiplier) calls `countDecimals()` on a string (MPMB adds it to Number only), so it throws whenever the value is a plain number; Acrobat shows the unformatted value, as the app does. The app's Messages card lists the error. Not reported to Joost yet.
- **Direct Import (Import/Export) needs two documents at once**: MPMB's `DirectImport` opens the other sheet with `app.openDoc` and reads its fields and its MPMB globals (`docFrom.CurrentVars`, `docFrom.What(...)`, `docFrom.isTemplVis(...)`) while it changes this one. The engine's `opts.openDoc` returns another engine's global (each sheet in its own realm; the app uses two hidden same-origin iframes, `ui-import.js`, as a worker has only one realm). MPMB checks `docFrom.toString() === "[object Doc]"` and `docFrom.info.title` (lower case: Acrobat's info answers the standard keys in lower case too). The import runs `ResetAll`, re-applies attacks before classes (a cantrip's ability stays empty: its final `ReCalcWeapons(false)` keeps the field), doesn't copy limited-feature uses, and only re-adds the sheet's default automation (`CurrentEvals`) at the next opening; the app reopens the result, as Acrobat would.
- **`checkThisBox(n, 0)` unchecks**: any false-ish value, not only `false`. MPMB's `SetProf("advantage")` passes 0 for "neither"; before, clearing conditions (`ConditionSet(true)`, in Reset and the import) ticked every skill's Adv and Dis box (passive Perception +5).
- A Calculate script that sets `event.richValue` sets the value to the spans' text (Acrobat); MPMB's "10 FT SPEED" labels read empty after a reset otherwise.
- MPMB bug: emptying the script in `AddUserScript` calls `InitiateLists()` without re-running the imported files, so their content vanishes until reopening and the next source update resets their default exclusions. `content.js` removes a pasted script with the file dialog's steps instead.
